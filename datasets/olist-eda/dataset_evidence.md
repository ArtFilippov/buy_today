# Источники и воспроизводимость EDA Olist

## Вопрос и снимок

Общий обзор собранного датасета с акцентом на рекомендательную систему:
качество, влияние отбора, распределения, время, география, реальные истории
и покрытие будущих покупок обучающей историей. Фокус подтверждён пользователем.

Исследуется локальная `dataset/olist_prepared_dataset.csv`: **96 068 × 35**,
84 130 заказов, 81 541 пользователь, 30 991 товар. Единица — позиция заказа,
ключ `(order_id, order_item_id)`. Источник — [Olist на Kaggle](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce).
Точная версия публикации и дата скачивания неизвестны. Снимок локальных файлов
зафиксирован SHA-256 в [input_manifest.json](input_manifest.json), дата аудита 2026-09-20.

SHA-256 подготовленной таблицы:
`9d47d6e021253339beeb7e5da4f16fa00f890a11364581c18ae5a0e46b5fd019`.

## Исходная сборка

[prepare_data.ipynb](../../prepare_data.ipynb) документирует подготовку:

1. По **всем** исходным позициям подсчитано число продавцов каждого товара.
2. Сохранены delivered-заказы и позиции товаров ровно с одним продавцом.
3. Присоединены покупатели, товары и продавцы с `many_to_one`.
4. Геосправочник предварительно свёрнут по почтовому префиксу: медианы
   координат, наиболее частая пара город–штат, алфавитное разрешение равенства.
5. Категории переведены, неизвестный перевод заменён оригиналом. Пропуски сохранены.
6. Удалены `seller_id`, `shipping_limit_date`; платежи и отзывы не присоединены.

Исходная таблица читается целиком; случайной выборки в EDA нет. Аналитические
преобразования и отсечения применяются локально к конкретным показателям.

## Вспомогательный датасет: source_reference.csv.gz

**112 650 строк × 11 столбцов**, та же единица позиции. Создаётся
[collect_reference.py](collect_reference.py) из:

| Локальный файл в `dataset/` | Использование |
| --- | --- |
| `olist_order_items_dataset.csv` | Ключ позиции, товар, продавец, цена, доставка |
| `olist_orders_dataset.csv` | Статус, время покупки, customer_id |
| `olist_customers_dataset.csv` | Связь customer_id → customer_unique_id |
| `olist_products_dataset.csv` | Исходная категория товара |
| `product_category_name_translation.csv` | Перевод категории |
| `olist_prepared_dataset.csv` | Независимая проверка набора ключей и значений |

Все соединения проверяются как `many_to_one`, предварительно проверены
уникальность справочников и полное покрытие ключей. Набор исходных позиций
не сокращается. `source_seller_count` рассчитан до любого фильтра, `kept` —
признак соответствия фильтрам сборки. Категория сохраняет исходные пропуски.
`customer_id` после соединения удалён из вспомогательной таблицы.

Проверено **точное совпадение ключей** `kept=True` с подготовленной таблицей,
а также товара, пользователя, цены, доставки, времени покупки и категории.
Это не повторная независимая проверка каждого географического агрегата:
их исходная логика находится в `prepare_data.ipynb`.

## Запуск

Окружение проекта: Python ≥3.13, зависимости `pyproject.toml` / `uv.lock`.
Использовано установленное `.venv`: pandas 3.0.6, numpy 2.5.3, matplotlib 3.11.2,
nbformat 5.11.1, nbclient 0.11.0, ipykernel 7.3.0. Все команды — из корня репозитория.

```bash
uv sync --frozen
.venv/bin/python datasets/olist-eda/collect_reference.py
MPLBACKEND=Agg .venv/bin/python notebooks/olist-eda/explore.py
.venv/bin/python notebooks/olist-eda/build_report.py
```

Первый шаг сбора требует уже распакованные исходные CSV и подготовленную
таблицу. Он не загружает интернет-источники и не изменяет их.
Второй шаг сохраняет исследовательские PNG и численные результаты.
Третий собирает notebook из проверенного кода и исполняет в новом ядре того
же Python. Для обычного повторного запуска `report.ipynb` достаточно двух
готовых входов: подготовленного CSV и `source_reference.csv.gz`.
Notebook не запускает сборку или исследовательский скрипт через import.

## Границы интерпретации

- Статус delivered — условие отбора; данные не описывают весь спрос.
- Фильтр по всем продавцам за всю историю использует будущее относительно
  любого промежуточного train-среза. Cold-start-аудит условен на таком отборе.
- Позиции не являются независимыми заказами; товарные характеристики отдельно
  проверены на согласованность и анализируются также с одним весом на товар.
- Выгрузка не содержит исторического каталога, экспозиций и остатков.
  Товар с нулём продаж неизвестен; первая продажа не дата появления товара.
- Пропуски не импутируются. Их механизм неизвестен; отсутствие географии
  может отражать неполноту справочника. Отдельные координаты подозрительны.
- Проверка рамки Бразилии `lat∈[-34,6], lng∈[-74,-34]` — грубая диагностика,
  не проверка принадлежности государственной границе. Исключены 4 позиции
  только из расчётов расстояния; ещё 493 не имеют всех координат.
- Нулевая масса (8 позиций) отмечена отдельно; в корреляциях и группах массы
  не интерпретируется как физический ноль. Бесплатная доставка допустима.
- Фактические последующие даты недоступны в момент рекомендации.
- Дата среза статусов и часовой пояс неизвестны; крайние месяцы неполные,
  последние когорты могут иметь незавершённые доставки вне итогового отбора.
- Ассоциации описательные. Проверки подгрупп и чувствительности не устраняют
  все смешивающие факторы и не устанавливают причинность.
