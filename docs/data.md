# Данные и подготовка

[README](../README.md) · [Локальный CLI](local-cli.md#подготовка) · [Конвейер](pipeline.md)

## Источник и единица наблюдения

[Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)
содержит около 100 тыс. реальных анонимизированных заказов за 2016–2018 годы.
Источник удовлетворяет требованиям задания к табличным данным: CSV, более
10 000 строк и 10 признаков, категориальные поля, время и пропуски до очистки.

Единица рабочего датасета — **позиция заказа**, ключ — `(order_id, order_item_id)`.
`customer_unique_id` обозначает реального покупателя Olist, `product_id` — товар,
`order_purchase_timestamp` — исходное время покупки. Идентификаторы служат для
связей и индексации, а не автоматически становятся признаками расстояния.

Из реальных позиций генератор создаёт [модельные истории](pipeline.md#модельные-истории).
Их `user_id` синтетический, а порядок событий задаёт `event_index`.
Отбор `delivered` и единственного продавца ретроспективен: текущий эксперимент
не является оценкой рекомендаций на реальных будущих покупках пользователей.

## Исходные файлы

Для локального запуска распакуйте Olist в `dataset/`. `prepare` использует семь файлов:

| CSV | Содержание |
| --- | --- |
| `olist_order_items_dataset.csv` | Позиции заказов, товары, продавцы, цены и доставка |
| `olist_orders_dataset.csv` | Статус, даты и связь с покупателем |
| `olist_customers_dataset.csv` | Идентификаторы и адреса покупателей |
| `olist_sellers_dataset.csv` | Адреса продавцов |
| `olist_geolocation_dataset.csv` | География почтовых префиксов |
| `olist_products_dataset.csv` | Категории и характеристики товаров |
| `product_category_name_translation.csv` | Переводы категорий на английский |

`olist_order_payments_dataset.csv` и `olist_order_reviews_dataset.csv` входят
в исходную поставку, но в подготовке не участвуют. Исследовательский
`olist_prepared_dataset.csv` также не требуется: рабочая таблица собирается заново.
[Docker](docker.md#образ-и-сборка) скачивает все девять исходных CSV при сборке.

## Правила подготовки

```bash
uv run buy_today prepare --raw-dir dataset --output-dir data/olist-stream \
  --batch-size 5000 --min-category-count 1000
```

1. Оставляются позиции заказов `delivered` и товары с единственным продавцом
   **во всей исходной истории позиций**, включая недоставленные заказы.
2. Присоединяются покупатели, продавцы, товары и география. Проверяются ключи,
   ссылки на справочники и соединения `many_to_one`.
3. Почтовые префиксы сохраняются пятизначными строками. По префиксу вычисляются
   отдельные медианы координат и наиболее частая пара «город–штат»;
   при равенстве частот выбирается первая пара по алфавиту.
4. Категории переводятся на английский; без перевода сохраняется оригинал.
5. Выбираются ровно 35 колонок. Строки с любым пропуском в них удаляются;
   пропуски в исключённых полях на очистку не влияют.
6. По всему очищенному датасету считаются частоты переведённых категорий — число
   позиций заказа. Категории с частотой **меньше `min_category_count`** удаляются;
   ровно на пороге сохраняются. Фильтр применяется один раз до разбиения.
7. Строки сортируются по `order_purchase_timestamp`, `order_id`, `order_item_id`.
   Отфильтрованный рабочий датасет сохраняется целиком.
8. Первый батч содержит `N // 2` строк. Остаток делится на полные батчи размера
   `batch_size`. Неполный хвост отбрасывается из потока, но остаётся в рабочем CSV.
   Позиции одного заказа могут попасть в разные батчи.

Размер батча и порог категории — положительные целые. Порог `1` сохраняет все
категории очищенного датасета; после фильтров должны остаться минимум две строки.
Если остаток меньше размера батча, поток состоит только из первого батча.
Число строк и батчей рассчитывается для переданных CSV, а не задано константами.

## Схема и все 35 признаков

Порядок и типы фиксирует [schema.py](../src/buy_today/schema.py). CSV записываются
в UTF-8 без индекса DataFrame, даты — `YYYY-MM-DD HH:MM:SS` без часового пояса.
`read_dataset` восстанавливает строковые коды, даты и числа с
`float_precision="round_trip"`. `order_item_id` — `int64`, даты — `datetime64[ns]`,
остальные числовые поля — `float64`, идентификаторы и категории — `string`.

Ниже — утверждённый набор и возможные применения полей. Сохранение столбца
не означает использование его как признака текущего ранжировщика: Random/SVD
работают с user–item-взаимодействиями. Статус, подтверждение оплаты и фактическая
доставка описывают ход/результат покупки и недоступны при её оформлении.

| Признак | Краткое описание | Для чего может понадобиться |
| --- | --- | --- |
| `order_id` | Идентификатор заказа | Объединение позиций; вместе с `order_item_id` образует ключ строки |
| `order_item_id` | Номер позиции внутри заказа | Различение позиций и повторных единиц товара; проверка дубликатов |
| `customer_id` | Покупатель в рамках конкретного заказа | Связывание заказа с записью покупателя |
| `customer_unique_id` | Сквозной идентификатор реального покупателя | Объединение заказов человека; исследование реальных историй |
| `product_id` | Идентификатор товара | Матрица user–item, популярность и идентификация рекомендаций |
| `price` | Цена позиции, BRL | Сравнение покупок по цене; моделирование ценовых предпочтений |
| `freight_value` | Стоимость доставки позиции, BRL | Расходы на доставку и итоговая стоимость покупки |
| `order_status` | Статус заказа; после подготовки `delivered` | Контроль выборки; в рабочем наборе не различает покупки |
| `order_purchase_timestamp` | Дата и время оформления | Временная сортировка, батчи, сезонность, исходное время Olist |
| `order_approved_at` | Подтверждение оплаты | Задержка подтверждения; известно после оформления |
| `order_delivered_carrier_date` | Фактическая передача перевозчику | Скорость обработки заказа; этап после покупки |
| `order_delivered_customer_date` | Фактическая доставка покупателю | Срок доставки и опоздание; результат покупки |
| `order_estimated_delivery_date` | Обещанная дата доставки | Ожидаемый срок; сравнение с фактической доставкой |
| `customer_zip_code_prefix` | Пять цифр почтового индекса покупателя | Присоединение географии; код, а не числовая мера расстояния |
| `customer_city` | Город из таблицы покупателей | Локальные предпочтения и географическая группировка |
| `customer_state` | Штат из таблицы покупателей | Региональные различия с небольшим числом категорий |
| `customer_geolocation_lat` | Медианная широта префикса покупателя | География спроса; приблизительное расстояние до продавца |
| `customer_geolocation_lng` | Медианная долгота префикса покупателя | Географические расстояния и пространственная группировка |
| `customer_geolocation_city` | Город из наиболее частой пары «город–штат» | Согласованность адресных данных; дополнительная география |
| `customer_geolocation_state` | Штат из той же пары | Проверка соответствия `customer_state` |
| `seller_zip_code_prefix` | Пять цифр почтового индекса продавца | Присоединение географии; территория отправления |
| `seller_city` | Город из таблицы продавцов | Место отправления и региональная доступность |
| `seller_state` | Штат из таблицы продавцов | Группировка; совпадение регионов покупателя и продавца |
| `seller_geolocation_lat` | Медианная широта префикса продавца | Расположение продавца; расстояние до покупателя |
| `seller_geolocation_lng` | Медианная долгота префикса продавца | Географические расстояния и пространственная группировка |
| `seller_geolocation_city` | Город из наиболее частой пары «город–штат» | Согласованность адреса продавца; дополнительная география |
| `seller_geolocation_state` | Штат из той же пары | Проверка соответствия `seller_state` |
| `product_category_name` | Категория, по возможности на английском | Тематическая близость и предпочтения по категориям |
| `product_name_lenght` | Длина названия, символы | Оформление карточки товара |
| `product_description_lenght` | Длина описания, символы | Подробность карточки товара |
| `product_photos_qty` | Число фотографий | Полнота визуального представления |
| `product_weight_g` | Вес, граммы | Физические характеристики и факторы стоимости доставки |
| `product_length_cm` | Длина, сантиметры | Габариты, объём и пропорции |
| `product_height_cm` | Высота, сантиметры | Габариты, объём и пропорции |
| `product_width_cm` | Ширина, сантиметры | Габариты, объём и пропорции |

Написание `product_name_lenght` и `product_description_lenght` сохранено из Olist.

## Результаты и метаданные

```text
data/olist-stream/
├── working_dataset.csv
├── manifest.json
├── state.json
└── batches/
    ├── batch_000.csv
    ├── batch_001.csv
    └── ...
```

| Поле `manifest.json` | Содержимое |
| --- | --- |
| `format_version` | Версия `1` |
| `sources` | Абсолютный исходный каталог, семь файлов и число строк; пути относительно источника |
| `schema` | Упорядоченные 35 колонок и их типы |
| `parameters` | Размер батча, правило первого батча, `drop_last`, сортировка, очистка, порог категории |
| `statistics.stages` | Строки, заказы и товары на этапах source/delivered/единственный продавец/сборка/`cleaned`/`category_filtered` |
| `statistics` | Исключённые заказы/товары, пропуски до очистки, удалённые строки, категории до/после фильтра, размер хвоста |
| `working_dataset` | Путь, число строк, начало и конец периода |
| `batches` | Упорядоченные `id`, `path`, `rows`, `period_start`, `period_end` |

Пути результатов относительны к каталогу манифеста. Поток определяется списком
`batches`, а не всеми CSV на диске. Повторная подготовка перезаписывает одноимённые
файлы; старые батчи вне нового манифеста могут остаться и не входят в новый поток.

`state.json` подготовки содержит `{"next_batch_index": 0}` и сбрасывается при
повторном `prepare`. Полный `run` хранит **собственное** состояние в каталоге прогона.
Для оценки накопленного шага используется его `reference.csv`: рабочий CSV
содержит также ещё не поступившие строки и отброшенный хвост.

## Python API

```python
from pathlib import Path
from buy_today.preparation import prepare_data
from buy_today.schema import read_dataset

result = prepare_data(
    Path("dataset"), Path("data/olist-stream"), batch_size=5000,
    min_category_count=1000,
)
working = read_dataset(result.working_dataset_path)
```

`PreparationResult` содержит пути рабочего CSV и манифеста, число строк до
очистки, после удаления пропусков и после фильтра категорий, число категорий
до/после фильтра, размеры батчей и хвоста. Проверки отчётов описаны в
[EDA и эталоне](pipeline.md#eda-и-эталон).
