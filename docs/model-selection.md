# Подобранная связка генератора и ранжировщика

**Рекомендуемая конфигурация для первого батча и синтетических повторных покупок:**

- **Расстояние:** `CategoryPriceDistance`.
- **Температура генерации:** `0.1`.
- **Ранжировщик:** `SVDRanker(n_components=256, n_iter=7, random_state=42)`.
- **История:** 70 train / 15 validation / 15 test событий на пользователя.
- **Оценка:** полный каталог, `K=10`, купленные товары остаются кандидатами.

Расстояние между позициями заказов:

$$
d(a,b)=\mathbf{1}[category_a\ne category_b]
       +|\log(price_a)-\log(price_b)|.
$$

Вероятность выбора позиции пропорциональна `exp(-d / 0.1)`.
Расстояние безразмерное, не зависит от единицы цены, не использует ID товаров,
покупателей или якорей. Это расстояние по признакам: разные товары с одинаковой
категорией и ценой могут иметь нулевое расстояние. `fit` не обучает параметры.

## Измеренные результаты

Полный первый батч: **41 387 позиций, 14 314 товаров, 20 категорий**.
Первичный подбор: 11 генераторов × 9 ранжировщиков × 3 seeds, по 1000 пользователей.
Затем уточнение T=.1/.15/.2 и SVD128/256/384 с контролем личной частоты.
Параметры зафиксированы в `notebooks/model-selection/selection.json` **до test**.

Финальная проверка: новые seeds **73, 211, 907**, по **2000 пользователей**;
каждая модель обучена только на 70 train-событиях этих пользователей.
Средние test-метрики на **одинаковых датасетах выбранного генератора**:

| Ранжировщик | NDCG@10 | Recall@10 |
| --- | ---: | ---: |
| **SVD256** | **0.49359** | **0.37208** |
| Личная частота + популярность для разрешения ничьих | 0.47012 | 0.34941 |
| SVD32 | 0.22187 | 0.17598 |
| Общая популярность | 0.03316 | 0.03319 |
| Random | 0.00086 | 0.00078 |

SVD256 выигрывает у личной частоты на каждом seed. Средний прирост NDCG —
**0.02347, или 5.0% относительно baseline**. Диапазон NDCG по seed: 0.49064–0.49757.
Парный bootstrap по пользователям, стратифицированный по seed, даёт условный
95% интервал разности **[0.02076, 0.02619]**. Это неопределённость оценки трёх
фиксированных моделей на синтетике, не интервал качества на реальных людях.

Текущая стандартная связка TimestampDistance / 86400 секунд + SVD32 получила
test NDCG=0.12643, Recall=0.07529. **Это другой датасет:** разницу нельзя целиком
приписывать улучшению ранжировщика.

## Почему датасет пригоден для этого эксперимента

Пороги были заданы до просмотра результатов. На каждом из трёх финальных seeds:

| Проверка по train | Результат | Заданный порог |
| --- | ---: | ---: |
| Медиана уникальных товаров в 70 покупках | 39–40 | ≥30 |
| 10-й перцентиль уникальных товаров | 20 | ≥10 |
| Средняя доля самого частого товара пользователя | 16.65–17.48% | ≤20% |
| TVD распределения категорий относительно исходного батча | 0.0277–0.0439 | ≤0.10 |
| Покрытие исходного каталога train-покупками | 94.17–94.69% | диагностический показатель |

Составное расстояние с дополнительным временем и T=.2 давало более высокую
метрику личной частоты, но не прошло ограничение концентрации (>20%) и было отклонено.

**Граница применимости:** около 99.9% покупок пользователя лежат в категории
его якоря. Это синтетика узкого интереса, а не реалистичная многокатегорийная
корзина. Большинство попаданий — повторные покупки. Recall@10 по товарам,
ещё не купленным пользователем в train, — **0.06045** у SVD и 0 у личной частоты;
считается по пользователям с хотя бы одним таким релевантным товаром.
Качество на реальных историях и поздних малых батчах не измерено. Для них параметры
генерации нужно проверять отдельно. Выбранные gates не доказывают реалистичность.

## Готовые артефакты и использование

| Артефакт | Путь от корня |
| --- | --- |
| Расстояние | `models/model-selection/distance.joblib` |
| Датасет основного запуска | `data/model-selection/seed_73/` |
| Обученный SVD и manifest | `models/model-selection/seed_73/ranking/` |
| Официальные оценки | `models/model-selection/seed_73/ranking/{validation,test}/` |
| Выполненный notebook | `notebooks/model-selection/report.ipynb` |
| Самодостаточный HTML-отчёт | `notebooks/model-selection/report.html` |
| Таблицы экспериментов | `notebooks/model-selection/*.csv` |

Аналогичные snapshots сохранены для seeds 211 и 907. Модели и датасеты находятся
в стандартных игнорируемых Git каталогах `models/` и `data/`.

Получить рекомендации уже обученной модели:

```bash
uv run --locked buy_today inference \
  --model-dir models/model-selection/seed_73/ranking \
  --user-id user_000000_000000 --k 10 \
  --output models/model-selection/example_recommendations.csv
```

Сгенерировать новый снимок и обучить выбранный ранжировщик стандартными командами
(каталоги назначения должны быть новыми):

```bash
uv run --locked buy_today generate \
  --batch data/olist-stream/batches/batch_000.csv \
  --distance models/model-selection/distance.joblib \
  --output-dir data/model-selection/new-run \
  --temperature 0.1 --n-users 2000 --random-state 73

uv run --locked buy_today rank \
  --dataset-dir data/model-selection/new-run \
  --output-dir models/model-selection/new-run \
  --model svd --svd-n-components 256 --svd-n-iter 7 --random-state 42
```

## Воспроизведение исследования

Нужно установленное окружение проекта и существующий `data/olist-stream/`.
Проверенная версия входного батча и её SHA-256 записаны в `screening_manifest.json`.

```bash
uv run --locked python notebooks/model-selection/prepare_data.py
uv run --locked python notebooks/model-selection/refine.py
uv run --locked python notebooks/model-selection/finalize.py
uv run --locked python notebooks/model-selection/explore_plots.py
uv run --locked python notebooks/model-selection/build_report.py
```

Первичный подбор и уточнение продолжают уже завершённые конфигурации по сохранённым
CSV; для полностью нового исследования используйте отдельную копию каталога результатов.
`finalize.py` создаёт отсутствующие датасеты/модели и пересчитывает оценки.
`build_report.py` не запускает обучение и генерацию: только читает подготовленные
таблицы, строит графики кодом в notebook и выполняет его в свежем ядре.

Происхождение данных: `datasets/model-selection/dataset_evidence.md`.
Семантика графиков: `visualizations/model-selection/data_context.md`.
Ход исследования и визуальные проверки: `notebooks/model-selection/_work/analysis_notes.md`.
